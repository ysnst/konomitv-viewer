# KonomiTV Viewer (iOS)

KonomiTV サーバー向けの、視聴専用のネイティブ iOS アプリです。
個人が趣味で作っている非公式のアプリで、KonomiTV 本体 (tsukumijima さん作) とは別のプロジェクトです。使うには、別途 KonomiTV サーバーが必要です。

## このフォークについて

このリポジトリは、tatsuya0902 さんの [KonomiTV Viewer](https://github.com/tatsuya0902/konomitv-viewer) をベースにした、**本家とは独立した非公式フォーク**です。[KonomiTV PWA](https://github.com/tsukumijima/KonomiTV) に近い操作性を目標に、録画番組の管理、ネイティブプレイヤーの機能、日常利用時の使いやすさを改善しています。

HEVCのネイティブ再生、各種認証、設定・視聴履歴・マイリストの同期、録画予約などは本家から引き継いだ機能です。以下では、フォークで追加した機能と既存機能の改善を分けて説明します。

## 本家からの主な変更点

### 録画ホーム・一覧

- **録画ホームを追加**。最近の録画10件、マイリスト4件、視聴履歴4件を表示し、検索と「もっと見る」から既存の一覧へ進めます。表示中は30秒ごとに更新し、更新時のスクロール位置を保ちます。
- **進捗表示を改善**。既存の視聴履歴・再生位置の双方向同期を維持し、PWAで更新した最後の再生位置もサムネイル下の進捗バーへ反映します。履歴はまとめて取得します。
- **ページ送りを改善**。既存のサーバー側30件単位のページネーションを維持し、上下に先頭・末尾への直接移動を追加しました。「ページ切り替え時に先頭へ移動」がONなら一覧全体の最上部へ、OFFなら操作したページネーションの画面内位置を保ちます。
- タブ切り替えや再生画面から戻る際は、ページ・スクロール位置・検索・フィルター・並び順を保持します。ホームから新たに一覧を開く際は1ページ目から始めます。録画全体を毎回取得しない構成で、大量の録画がある環境の操作性に配慮しています。

### プレイヤー・字幕・実況コメント

- 時間表示と主要操作を映像下端側のオーバーレイへ集約。細いシークバーを映像下端に配置し、既存のコメント密度グラフはシーク操作中だけ表示します。番組情報・コメントの切り替えタブは画面最下部へ固定しました。
- 画質・速度・実況コメント関連設定、音声のみ再生、おやすみタイマーなどを設定メニューへ集約。通常画面では映像を覆わない固定パネル、全画面ではスクロール可能なパネルで、映像を確認しながら操作できます。ヘッダー・ステータスバーの視認性とSafe Areaへの対応も改善しました。
- **リピート再生とプレイヤー再起動を追加**。再起動は設定メニューの最下部にあります。既存の再生・停止、秒数スキップ、前後の番組移動などは維持しています。
- 録画の全画面表示で実況コメントが消える問題を修正。通常画面・全画面で字幕と実況コメントを切り替え、同じ表示設定を共有します。シーク時の古い字幕の無効化、移動先に応じた復元、連続シーク・非同期イベントの処理を改善しました。字幕残留は0.20で実機解消を確認済みです。

映像内の操作ボタンは、左から **通常キャプチャ → 実況コメント付きキャプチャ → 実況コメント表示 → 字幕表示 → プレイヤー設定 → PiP → 全画面** の7つです。利用できない機能は状態に応じて無効になります。

### Picture in Picture（PiP）

**iOS標準PiPを追加**し、VLCKitを4.0.0a26へ移行しました。HEVC録画・生放送のVLCKit経路と、H.264録画のAVPlayer経路を実装しています。バックグラウンドでの再生継続、元のプレイヤーへの復帰、録画PiP中の視聴位置保存・同期に対応します。HEVC録画は実機確認済みですが、H.264・生放送のPiPは実機未確認です。PiP内の字幕・実況コメントは未対応です。

### キャプチャ

**通常・実況コメント付き・字幕付きのキャプチャを追加**しました。映像内のボタンから撮影し、保存先をKonomiTVサーバー、iOS写真ライブラリ、両方から選べます。保存先・字幕保存モードのPWAとの設定同期、JPEG・EXIFメタデータ、Cloudflare Access経由のサーバー保存に対応します。写真・両方保存の現行版での個別実機検証は未完了です。詳細は[キャプチャ仕様と制約](docs/capture-investigation.md)を参照してください。

### 視聴履歴・設定

既存の同期機能を使った進捗反映・取得管理を改善しました。履歴保持件数は選択式から数値直接入力へ変更し、PWAと同期した値を表示します。確定・キャンセル、不正値の検証、件数を減らす際の確認を設け、入力途中で保存・履歴削除が起きないようにしています。本家KonomiTVの正の整数という仕様に合わせ、Viewer独自の件数上限は設けません。ただし端末の整数表現範囲や、大量履歴の通信量・URL長・性能の制約はあります。[構成と制約](docs/architecture.md)も確認してください。

### ビルド・品質管理

既存のActionsによる未署名IPA生成を、公開処理から分離しました。作業ブランチでのビルド、完全コミットSHA・SHA-256・バージョン・build番号・IPA内外の来歴照合を追加しています。視聴履歴、ページ位置、字幕タイムライン、キャプチャメタデータの自動テストとJPEG・EXIF互換性の検証、実機検証記録を整備しました。ビルド成功と実機動作確認は区別します。

主な確認環境はiPhone 17 Pro、LiveContainer、HEVC録画、Cloudflare Access認証です。0.20の16項目はすべて成功しましたが、追加検証で字幕同期ずれが報告されています。

## 既知の問題・技術的制約

- **シーク後の字幕同期ずれ**：字幕の表示タイミングがずれる場合があり、再生し直すと戻ることを確認しています。原因は未特定で、追加の実機情報が得られるまで修正を保留しています。修正済みの「古い字幕が残る問題」とは別件です。[調査報告](docs/subtitle-sync-investigation.md)を参照してください。
- **PiP内の字幕・実況コメント**：未対応です。通常画面・全画面の表示やPiPの映像再生とは別の制約です。
- **L字画面クロップ**：本家PWAの機能は未実装です。
- **未取得区間の字幕復元**：未取得の直前区間から続く字幕は、取得済みデータだけで完全に復元できない場合があります。
- **実機未検証の経路**：H.264録画・生放送の再生経路、現行版の写真・両方保存などには未確認項目があります。

## Web 版 (PWA) があるのに、なぜアプリなのか

KonomiTV は Web ブラウザだけでも見られます。このアプリは、iPhone のブラウザでは足りないところを補うためのものです。

- 全画面にしたときに、時計やアドレスバーが残らず、端末ごと横向きになります
- H.265 / HEVC の録画を、サーバーで変換せずそのまま再生できます (サーバーの負担が軽く、遅れも少なくなります)
- 字幕・文字スーパーを、映像に入っている字幕データから直接出します

## できること

- 録画番組: 一覧 (ページ送り・絞り込み・並び替え) と再生
  - マイリスト (あとで観たい番組の保存。一覧や再生画面から追加・削除できます)
  - チャプター移動、少し戻る／少し進む、シーク中のプレビュー、見ていた位置からの再開
  - 字幕・文字スーパーの表示、ニコニコ実況コメントの表示とコメント一覧
  - 録画中の番組の追いかけ再生、音声のみ再生
- 生放送: チャンネル一覧からの再生、全画面表示
- 番組表: Web 版と同じ格子状の番組表 (日付と種別の切り替え、表示設定)
- 録画予約: 予約一覧、番組表からの予約の追加・削除と有効／無効の切り替え (サーバーが EDCB バックエンドのときのみ)
- 設定: 画質・字幕・実況・アカウントなどの設定。KonomiTV アカウントでログインすると、設定・視聴履歴・マイリストを Web 版など他の端末と共通にできます
- 外からの接続: 設定の「認証方式」で Cloudflare Access のサービストークンか Basic認証、Digest認証、カスタムヘッダ、ブラウザでログイン、クライアント証明書、URLパラメータ (合言葉) を選ぶと、全ての通信にその方式の認証を付けて送ります (サーバーに Basic認証や Digest認証を掛けている環境や、自作のリバースプロキシで独自の合言葉ヘッダや URL のパラメータを見ている環境、ログイン画面で守られた環境、クライアント証明書が要る環境でも使えます。ただしクライアント証明書の方式では、データ放送の画面が通らない場合があります。また URLパラメータ (合言葉) の方式では、合言葉が URL に付くため、サーバー側の記録 (ログ) に残ることがあります)

## 拡張オプションについて

このアプリは1種類だけで、素の KonomiTV サーバーでそのまま使えます。

一部の追加機能 (録画の「保護」、ゴミ箱、前の話・次の話ボタンとしおり・場面一覧、録画結果一覧、チューナー使用中のチャンネル表示) は、[konomitv-customizations](https://github.com/tatsuya0902/konomitv-customizations) を適用した改造版サーバーが持つ受け口を使って動くものです。これらは、設定の「拡張オプション」の画面で、機能ごとのトグルをオンにしたときだけ出ます (既定はどれもオフです)。各トグルの下には、その機能に必要なサーバー側のカスタマイズの案内も出ます。そのサーバーを用意した人なら誰でも使えます。素の KonomiTV サーバーでは、サーバー側に受け口が無いため、オンにしてもそれらの機能は動きません。次回予約・シリーズ予約は、後ろ側が EDCB のサーバーであればトグルなしで使えます。

トグルのある区分は、最初は設定に出ていません。マイページの「App version」の行を7回タップすると解放され、設定の「このアプリの設定」に「拡張オプション」の行が追加されます (Android の開発者向けオプションと同じ出し方です)。専用画面の一番上の全体トグル「拡張オプションを使用」をオフにすると、行自体が消えて機能が全部止まり、機能ごとのトグルも全部オフに戻ります。再び使うには解放をやり直してください (機能ごとのトグルは全部オフの状態から始まります)。トグルの設定は端末だけに保存され、同期されません。

### 対応していないもの

Web 版にはあるものの、次の機能には対応していません。

- **X（旧 Twitter）への共有**: その共有は、ブラウザの Cookie をサーバーへ渡すアカウント連携が必要な仕組みのため、対応していません
- **サーバー全体の設定**: サーバーの管理そのものにあたるため、アプリからは扱いません。サーバー全体の設定など、サーバー側を扱うものは、従来どおり Web ブラウザから行ってください

## 入れ方 (LiveContainer)

署名なしの IPA で配布しているため、App Store のアプリのようには入りません。サイドロード用の入れ物が要ります。ここでは LiveContainer の例です。

1. LiveContainer を iPhone に入れる
2. このフォークの Actions の成功したビルドから Artifact `KonomiTV-Viewer-unsigned-ipa` をダウンロードし、中の IPA を取り出す。Releasesの案内を使う場合は、このフォークで公開されている対象版か確認してください。基準版0.20のビルドは[Actions run45650873099](https://github.com/ysnst/konomitv-viewer/actions/runs/45650873099)です
3. LiveContainer で IPA を開いて入れる

AltStoreやSideStoreなどを使う場合は、その仕組みに応じた署名・導入手順が必要です。このフォークでの個別の動作は未確認です。未署名IPAを通常のiOSへそのままインストールすることはできません。

## 使い方

1. 初回起動時に、接続する KonomiTV サーバーの URL を入力する (例: `https://example.com:7000`)。後からアプリ内の設定でも変更できる
2. サーバーに認証が掛かっている場合は、設定の「認証方式」で方式を選んで入力する。Cloudflare Access の場合はサービストークンの Client ID と Client Secret (Access 側には Service Auth のポリシーが必要)、Basic認証と Digest認証の場合はユーザー名とパスワード、カスタムヘッダの場合はヘッダ名と値の組 (2組まで、1組だけでも使える)。ブラウザでログインは、サーバーのログイン画面をアプリ内で開いてログインし、取り込んだ Cookie を通信に使う方式 (Cloudflare Access の対話ログインや Authelia などのログイン画面向け。ログイン画面がそのまま使えるかは環境によります)。クライアント証明書は、証明書ファイル (.p12) を取り込んで使う方式 (データ放送の画面はアプリが取り込んだ証明書を使えないため、この方式ではデータ放送が通らない場合があります)。URLパラメータ (合言葉) は、パラメータ名と値の組を接続先への全ての URL に付けて送る方式 (合言葉が URL に付く形のため、サーバー側の記録 (ログ) に残ることがあります)
3. 設定や視聴履歴を Web 版と共通にしたい場合は、設定の「アカウント」から KonomiTV アカウントでログインし、同期をオンにする

## ビルド

GitHub Actions の `Build (unsigned IPA)` は、作業ブランチを含む各ブランチへの push、Pull Request、手動実行で未署名 IPA を作ります。Windows では編集と Git 操作を行い、iOS のビルドは Actions の `macos-26-intel` と Xcode 26.6 で行います。Mac でビルドする場合は `KonomiTV-Viewer` で `pod install` を実行し、生成された `KonomiTV-Viewer.xcworkspace` を使ってください。

成功した実行の Artifact `KonomiTV-Viewer-unsigned-ipa` には、IPA、`build-info.json`、`checksums.txt`、依存版の `Podfile.lock`、ビルドログが入ります。版番号は `0.<ワークフローの実行番号>`、IPA 名にはコミット SHA の先頭12文字も含まれます。完全な SHA はアプリ内の `build-info.json` と Info.plist の `KonomiTVViewerCommitSHA` にも記録します。取得後は `python scripts/verify-ipa.py <展開先> --expected-sha <完全なSHA>` で、IPA のハッシュと内外の記録を照合できます（Python 3.11 以降）。

文書のみのpushでは、コミットメッセージに `[skip ci]` を付けると自動ビルドを抑止できます。ワークフローにパス除外はありません。

ビルドではタグやリリースを変更しません。公開は default branch から `Publish IPA (manual)` を明示的に手動実行したときだけ行います。この処理は対象コミットをビルドし直して検証し、実行ごとに新しい `ipa-<実行ID>-<試行番号>` タグとプレリリースを作ります。既存のタグ・公開済み IPA は移動、上書き、削除しません。新規の手動ワークフローを使うには、ワークフローファイルが default branch に入っている必要があります。
