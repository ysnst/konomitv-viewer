# 0.36のシーク後再生継続の調査

## 実機報告と範囲

[0.36の追加報告・訂正](testing/device-0.36.md)に従い、HEVC録画PiPは成功へ訂正。PiP修正は撤回した。対象は、再生中のシーク後に停止し、再生ボタンの追加操作で再開する場合がある問題だけ。段階Aの実機合格まで段階B以降へ進まない。

## 0.26と0.36の比較

0.26 `60ae8789dc3ec4e97b7a8853582667fcd90a5e98` と0.36 `eef1a0793ecc53247b30fc86993df20ef3b0660e` を比較した。スクラブ開始時の内部pause、終了時のseek完了前play、共通seek完了とVLC状態通知での再開は0.26にも存在する。0.36で追加したものではない。0.36では入力の開始・終了通知を確実にしたため、この既存経路を通る操作が増えている。

再開待ちの印は`.playing`で消去され、共通完了も`isPlaying`を条件にする。一方、スクラブ用pause/playとseekは同じ実行経路ではない。[固定版VLCKitの公開実装](https://github.com/videolan/vlckit/blob/4.0.0-a26/Sources/Playback/VLCMediaPlayer.m)では、pause/playをバックグラウンドの直列queueへ投入し、jump/setTimeは呼び出し側から渡す。stateはキャッシュ、isPlayingはlibVLCへの問い合わせである。したがって、一瞬のplaying観測だけではスクラブ操作全体の終了を表せない。ただし、**実機で発生した正確な通知順序は未取得**。同じqueue内でpauseが後続playを追い越した、あるいはPiPが原因だったとは断定しない。

## 最小修正

スクラブ専用のpauseと先行play、操作開始時の再生状態の保存を除去した。スクラブは表示位置を変更するだけとし、実際の再生/一時停止意図は変更しない。終了時は従来の共通seekへ渡し、完了時の再開判断も従来の世代・最新意図の確認を使う。操作中の再生ボタンも一時的な実状態ではなく最新の意図を参照する。

これにより、再生中は指の操作中も再生を維持し、停止中は停止を維持する。終了時のpreview/密度消去、字幕世代と直列seek、コメントreset、履歴の実時計は保持した。アプリ変更はPlayerViewControllerだけ。PiP、VLC描画入力、6ボタン、キャプチャ、通信、依存関係、保存形式は変更しない。恒常的な補正時間、再起動、再試行を追加していない。

## 検証と制約

native入力で再生中tap/drag、停止中tap/drag、連続seek、通常/全画面と表示終了を検証する。操作開始後の最新play/pauseは、実所有元と実エンジンを使う別の契約試験とし、実OSの複数指操作と区別する。停止維持は最新世代の共通シーク完了を待ち、実時計を3秒観測して判定する。初回の追加試験ではsetTime直後の仮時刻から観測して移動先への更新を再生進行と誤判定したため、観測開始条件を修正した。入力終了5秒、移動先15秒、停止時計3秒・許容差0.25秒は変更していない。完了通知は映像フレーム到着そのものを証明するものではない。旧版との比較では、スクラブ専用pauseの発行も観測するが、これは実機症状そのものの再現とは区別する。

再試験では6件中5件が成功し、残る通常seekの4回目は自動非表示の直前に座標を取得したため入力が届かなかった。操作帯を実際の映像tapで表示し直してから入力する試験へ修正した。アプリの3.5秒タイマーを無効化・延長していない。

実機でのHEVC再生、音声、PiP、認証、字幕/実況/履歴同期は新IPAで再確認する。過去の字幕同期ずれの原因解消は主張しない。PiPは回帰試験対象のみ。新IPAの自動試験結果・来歴は[段階Aチェックリスト](testing/stage-a.md)へ追記する。
