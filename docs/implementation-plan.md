# 改修の順序と検証境界

## 引き継いだ成果

IPA0.4ではHEVCの全画面コメントをユーザーが確認済み。IPA0.6では録画ホーム、検索/もっと見る、進捗、双方向同期、更新時スクロール、大量録画、HEVC/全画面、認証、設定保持の9項目を確認済み。記録はtesting/fullscreen-comments.mdとtesting/device-0.6.md。

## 今回のフェーズ

1. A: ページ送りの自動スクロール設定、新規遷移と復帰の分離、全画面の字幕/コメント操作、映像内の操作、共有設定、ヘッダー/ステータスバー。IPA0.8/build8をPiP前の候補として保存した。
2. B: 録画HEVC→生放送→録画H.264の順で標準PiPを接続。VLCKit4.0.0a26とAVPlayerLayerを使い、IPA0.11/build11を別保存した。
3. C: 通常/コメント付きキャプチャ、リピート、設定最下部のプレイヤー再起動を追加。各機能を個別コミットし、独立レビューと統合ビルドを行う。

L字クロップとPiP内字幕/実況の合成は、別の座標・描画処理を必要とするため後回しとする。部分対応のダミー項目は表示しない。検証境界と本家との差はtesting/player-features.md、PiPの版固定・採用方式・代替案はpip-investigation.md。

VLCKit3.7.5のUIView/OpenGLから、公式4.0.0a26のVideoToolbox/CVPX/AVSampleBuffer経路へ移行した。4系はalpha配布であり、ソースの対応とビルド成功だけで既存再生の実機互換を保証しない。HEVC/生放送を優先して端末確認し、H.264の新規素材・再エンコードは用意しない。

## 維持する契約

Bundle ID、保存済み接続先・認証・設定、ネイティブHEVC/H.264/生放送再生、字幕・実況・データ放送、密度グラフ・シーク・区間・既存移動操作、Cloudflare Accessサービストークン、中継、履歴双方向同期、録画ホーム/一覧/検索/ページ分けを維持する。最大到達位置の独自APIと本家の最終再生位置を混同しない。

数千件以上の録画を前提とし、ホームや進捗のために全ページを取得しない。明示ページ送りと自動更新/復帰の位置を区別する。

main、既存タグ、公開済みIPAは変更しない。公開ワークフローと本家PRは実行しない。各フェーズのIPAは上書きせず、完全SHA・埋め込み来歴・ハッシュを照合してローカルへ保存する。ソースレビュー、単体テスト、ビルド、ユーザーの実機結果を分けて報告する。
