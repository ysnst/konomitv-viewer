# 改修の順序と検証境界

## 現在の対象

1. IPA 0.4 のユーザー実機確認を `testing/fullscreen-comments.md` に記録する。
2. PWA と同じ最終再生位置由来の視聴進捗を、既存の録画カードで共通表示する。
3. 録画タブの初期画面に、新着10件・マイリスト4件・履歴4件のホームを追加する。既存の各一覧へ遷移し、起動時の選択タブは変えない。
4. 改修ごとに独立レビュー、テスト、個別コミットを行い、フォークの作業ブランチで Actions ビルドする。IPA は完全な SHA とハッシュを照合してローカルへ取得する。

数千件以上の録画を前提とし、ホームや進捗表示のために録画の全ページを取得しない。既存のページ送り、認証付き API、サムネイル取得経路を利用する。

## 次の PiP 対応

今回 PiP は実装しない。実際の利用環境に合わせ、優先順位を次の順にする。

1. 録画 HEVC の VLCKit 経路
2. 生放送の VLCKit 経路
3. 録画 H.264 の AVPlayer 経路

H.264 録画は利用環境に存在しないため、AVPlayer だけの PiP を先行成果とはしない。H.264 の動画作成・再エンコードは不要だが、既存対応は維持する。

現在のビルド実績は MobileVLCKit 3.7.5、libaribcaption 1.1.2。VLCKit 更新を伴う場合は、利用可能な配布版と PiP API、HEVC/TS、シーク、字幕、実況、データ放送、Cloudflare Access、ストリーム中継、LiveContainer 上の動作とリソース消費を先に調査する。依存更新と PiP の追加は今回の表示改修へ混ぜない。

## 維持する契約

Bundle ID、保存済み設定、既存データ、ネイティブの HEVC/H.264/生放送再生、字幕・実況・データ放送、Cloudflare Access サービストークン認証、視聴履歴の双方向同期を維持する。最大到達位置の独自 API と本家の最終再生位置を混同しない。

main、既存タグ、公開済み IPA を変更しない。公開ワークフローや本家向け PR は実行しない。ソースレビュー、ビルド、生成物照合、ユーザーによる実機結果を分けて記録する。
