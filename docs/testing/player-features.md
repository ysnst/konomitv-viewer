# プレイヤー追加機能とPiPの検証境界

フェーズAはIPA0.8/build8（b12b5dcbf2cb5e8ea27b980ce4e8c9f25281f4a2）をPiP前の候補として保存した。フェーズBはIPA0.11/build11（64e2c663a3a28b8a399914552079eb369d2bdc0d）。各ハッシュとCI URLはartifactsの完了報告へ残す。実機で成功したのは別記device-0.6.mdの9項目で、新版の動作を保証しない。

| 項目 | ソース上の対応 | 初期値・保存／差異 |
| --- | --- | --- |
| 画質／モバイル向け画質 | 既存操作を通常・全画面の設定へ集約 | 既存設定・プロファイルを維持 |
| 再生速度 | 録画の既存操作を設定へ集約 | 既存の端末保存。生放送の速度変更は追加しない |

## キャプチャの制約

- VLCは公開snapshot APIをObjCの@try境界で呼び、例外を失敗へ変換する。固有の一時パスを使い、約2秒で取得できなければ失敗とする。APIにPTSがないため、字幕・実況は要求時点の近似であり厳密なフレーム同期ではない。
- AVは要求中だけVideoOutputを付け、取得後・失敗・取消で除去する。停止中やシーク直後はフレームが得られないことがある。撮影のために勝手に再生を再開しない。
- 重い画像読込・変換・合成は背景処理。コメントUIViewだけをmainで控え、元映像のaspect-fit範囲をpixel寸法/scale1へ変換する。画面全体・操作UIは取得しない。
- PiP開始、画質・item・接続先・シーク等の変更で古い要求を拒否する。生放送のデータ放送中は映像窓と座標が異なるため撮影を無効にする。通常のデータ放送機能は維持する。
- 標準共有と「画像を保存」を使う。本家既定のUploadServerは追加しない。LiveContainerの公式通常ホストには写真用途説明があるが、利用中の版/起動方式は不明。ゲストBundle.mainの確認だけではホストの権限を検証したことにならない。
- 元解像度合成は4Kでメモリを使う。連打防止と後始末は実装済みだが、ピークメモリ、電力、発熱、保存時間は未測定。

## PiPの制約と検証表

HEVC/生放送はVLCKit4.0.0a26の公式サンプルバッファ描画、H.264は既存AVPlayerLayerを使う。依存更新はalphaであり、フェーズAへの切戻しを残す。詳細と不採用方式は../pip-investigation.md。

- 通常・全画面の開始/停止、準備前・失敗・5秒timeout、開始待ち中の離脱。
- バックグラウンド、別タブ、マイページ経由、元画面のpop、元タブへの復帰。
- 別番組へ移った際の二重再生防止、旧生放送へ戻る際の再開、停止/破棄後の解放。
- PiP中の位置/音声同期、10秒周期の履歴更新、終了時の最後の位置保存、PWAとの双方向同期。
- PiP内の字幕/実況は未対応。外側UIViewは標準PiPへ入らず、別のフレーム合成なしには表示できない。通常/全画面に戻ると元設定を維持する。
- VLC公開APIでは停止理由とUI復帰要求を区別できないため、正常開始後の停止では元画面へ戻す。AV側は専用復帰delegateを使う。
- 手動画質/プロファイル/音声のみ変更と再起動はPiP終了後に行う。追いかけ復旧が必要ならPiPを明示終了してから既存復旧を行う。
- HWデコードの経路は公式VideoToolbox/CVPXを維持し、CPUフレームコピー方式や再エンコードは追加しない。ただし実際にHWが使われたこと・性能・電力は実機未確認。

HEVCと生放送を優先して実機確認する。H.264の素材は作らず、実機対象外としてソース/ビルドで維持する。LiveContainerの通常ホスト/LiveProcess、ホスト側PiPとの競合、OS版と権限は端末で記録する。

## 検証の区別

独立レビューでPiP中のキャプチャ競合等を修正した。自動テストは履歴のFoundationテストとIPA照合テスト、actionlint、iOS Releaseビルド。新UI/PiP/キャプチャ/リピート/再起動の実行・描画・Photos保存はWindowsで確認できないため、すべて実機未確認として扱う。
