# 録画ホーム・進捗表示の検証

## ソース・自動テスト

- 本家基準: `KonomiTV@af98b172eb7a0e9df7683435c706c84bedd9231e` の Home、RecordedProgramList、RecordedProgram、Videos サービス。
- `HistoryStoreTests.swift`: 比率、0・負値・非有限値、履歴なし、不正要素、重複履歴、更新順、同時 GET の合流、保存前の旧応答拒否、認証・同期・接続設定の世代変更、失敗後の再試行、同期 OFF、最終 PUT と履歴一覧取得の競合。
- `test_verify_ipa.py`: IPA と SHA・ハッシュ・埋め込み情報の照合処理。
- コードレビュー: ホームは最大18番組を表示し、録画 API は各セクションの1ページのみ。空 IDs は送信しない。通常検索はサーバーの30件ページ分け。起動タブ `initialIndex: 1`、Bundle ID、既存の再生・認証・中継を維持する。

CI の実行 URL、完全 SHA、IPA の版とハッシュ、取得した依存版、実際の結果は各ビルドの `artifacts/` の検証記録へ残す。

## 実機で確認する項目

IPA 0.6 のユーザー実機結果9項目は device-0.6.md に記録済み。以下の表は引き続き新版の回帰チェックに使い、未報告項目まで成功扱いしない。

| 項目 | 期待結果 |
| --- | --- |
| 録画タブを開く | 新着10件→マイリスト4件→履歴4件。ホームには並べ替え・ページ送りがない |
| 各「もっと見る」 | 既存の録画一覧・マイリスト・履歴へ移動できる |
| 新着の検索 | 日本語、空白、C++、A&B 等で検索でき、30件単位のページ送りを使う |
| 検索中に文字を変更 | 古い応答が新しい検索結果を上書きしない |
| PWA で途中位置を変更 | Viewer の各カードのバーが最終位置に更新される。最大到達位置へ戻らない |
| Viewer で HEVC を再生・巻き戻し・終了 | PWA の履歴と続きの位置へ反映される |
| 履歴位置0・途中・末尾、履歴なし | バーの表示条件・色・3ptの太さ・配置が本家に準拠する |
| 履歴から削除、マイリスト追加・削除 | ホームと既存一覧へ反映される |
| 同期 OFF、ログアウト、別アカウント、接続先 A→B→A | 前の履歴・画像を残さず、古い通信結果も反映しない |
| 表示中に30秒待つ、非表示・バックグラウンドへ移動、復帰 | 表示中だけ定期更新し、復帰時に更新する |
| スクロール中・途中位置で更新 | 不必要に先頭へ戻らない |
| 初回読込・空・接続失敗・画像取得失敗・再試行 | 状態を区別し、更新失敗では既存内容を保つ |
| 数千件以上の録画 | ホームと通常検索で全録画を取り込まず、表示・操作が滞らない |
| 長い題名、狭い幅、横向き、表示倍率 | 見出し、操作、カードの重なり・見切れがない |
| HEVC の全画面コメント・解除・シーク・字幕・データ放送 | IPA 0.4 の修正と既存機能を維持する |
| 生放送、品質変更、回転 | 既存機能を維持する（引き続き実機未確認） |

H.264 は実機の対象動画がないため対象外。新規動画や再エンコードは用意せず、既存コードのレビューとビルドを継続する。Cloudflare Access と LiveContainer を使う利用環境で、端末・iOS 版・接続先サーバー版・IPA の完全 SHA とともに結果を記録する。

## 本家との差

ネイティブの単一列テーブルと既存カードを流用し、ホームだけ本家のまとまった面と区切りへ合わせる。本家のデスクトップ側ナビや複数列は対象外。カードのマイリスト操作・履歴削除は既存アプリと同様の長押しメニューで提供する。同期 OFF 時の端末専用視聴履歴は今回追加しない。スマートフォンでの外観一致は実機での確認が必要。
