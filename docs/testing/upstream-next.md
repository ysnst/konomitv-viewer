# IPA 0.26以降の追加更新チェックリスト

基準は[0.26の実機成功9項目](device-0.26.md)。今回生成する段階A（テスト基盤のみ）と段階B（HEVC fMP4/復旧追加）は別の実機確認対象で、以下はすべて新版の実機未確認とする。[取り込み内容・ビルド記録](../upstream-next.md)の完全SHAと版番号を対応させて確認する。

段階Aは0.27 / build 27、段階Bの旧候補は0.28・0.29。どのIPAを試したかを必ず記録し、別版の成功を転記しない。今回の停止修正・開始監視接合の成果物とCI結果は[0.29のUI停止調査](../smoke-0.29-investigation.md)で対応させる。

元のUI失敗はVLC描画ビュー独自のタップによるエンジン停止と特定した。入力を親の操作へ集約し、非同期開始後の自動非表示予約漏れも修正した。テスト操作が3.5秒の自動非表示を越えてボタンを押す競合も別途修正している。mainは0.26のまま維持する。

最新候補は**0.33 / build 33**、ビルド元`ff3ac274ff96c8e62d8d8e26de87d51e54877014`。[Release](https://github.com/ysnst/konomitv-viewer/actions/runs/45771877714)、[TSのUI成功](https://github.com/ysnst/konomitv-viewer/actions/runs/45771881750)、[停止復旧成功](https://github.com/ysnst/konomitv-viewer/actions/runs/45771885060)を確認した。一方、[fMP4/AACのAV単独経路試験は失敗](https://github.com/ysnst/konomitv-viewer/actions/runs/45771888213)で、復旧後のVLC再生をAV成功に数えない。0.33の実機項目は以下すべて未確認である。

本家`a2de08583aec2ea66c31ba9605acc84e394c5e15`の開始監視を取り込んだ。以下は新版の実機ではすべて**未確認**であり、シミュレーター・状態モデルの成功を転記しない。

## 今回の追加確認

- 操作帯が隠れた後の映像タップで、停止せず再表示されること。通常・全画面・復帰後と生放送で確認する。
- 非同期開始後は操作帯が自然に隠れ、一時停止時は表示されること。前後の長押しスキップを各3.5秒超続けても隠れず、両方向の操作終了後に通常の自動非表示と再生継続へ戻ること。
- 音声ありHEVC fMP4とTS/VLCを区別し、実サーバーのplaylistにMAPがあるかを確認する。公開標準サーバーはTSのため、fMP4成功と混同しない。
- 状態がplayingでも位置が進まない開始で、12秒の有効監視、一回の3秒待機retry、同じセッションのVLC復帰になること。無限再試行・二重再生がないこと。
- 監視開始11秒後など期限付近の一時停止、長時間停止、再開。停止中に再生・復旧を強制しないこと。
- 初期の途中再生、ready前のシーク、短距離・長距離・前後・連続・停止中のシーク。実際の最新完了を基準にし、失敗したseekを古い0秒で上書きしないこと。
- scrub・長押しスキップ中にretryの期限が来た後、指を離すと最新位置から保留復旧が再開すること。
- PiP開始待ち・継続中・画面非表示・アプリ非アクティブ中は項目を交換しないこと。復帰後も位置・停止意図を維持すること。
- 開始監視とkeep-aliveの失敗が同時に発生しても再構築が一度で、古い開始位置へ戻らないこと。接続・認証・番組変更や画面破棄後に旧タイマーが再生を復活させないこと。
- 6ボタン、字幕・スーパー・実況、撮影・保存設定、一覧・スクロール保持・履歴同期を以下の既存チェックでも確認する。

- 通常/全画面の切り替えと復帰、回転、Safe Area、6操作の順序、下端シーク、操作中だけの密度グラフ、下部タブ。
- 通常/全画面の設定、画質/速度/コメント/字幕/音声のみ/タイマー/再起動。
- 字幕残留が再発しないこと、字幕・文字スーパー・実況の表示と同期、字幕ON/OFF。同期ずれが再発した場合は[フェーズH](phase-h.md)の条件を記録する。再現しなくても原因解消と断定しない。
- HEVC PiP開始・継続・復帰、全画面からの移行、アプリ離脱・復帰、履歴同期、開始失敗時の通常再生維持。

- 録画ホーム10/4/4、検索/絞り込み/並び順、9ボタン、自動スクロールON/OFFの上下操作、一覧復帰・30秒更新時の位置保持。

- H.264/生放送の再生・PiPは実装と実機確認を区別する。H.264素材を新たに用意する必要はない。

## 段階Bで追加する確認

- 対応サーバーがHEVC要求のplaylistにEXT-X-MAPを返す場合のfMP4/AVPlayer開始。非対応サーバー・TS応答・probe失敗では従来VLC4へ戻ること。開始待ちの画質変更/停止/画面離脱/接続変更で古い要求が復活しないこと。
- fMP4の先頭/途中からの開始、開始前失敗→一度の待機再試行→VLC復帰。再試行中の停止/再生、最新seek、連打、手動再試行、中継失敗、バッファリング。
- fMP4の字幕・文字スーパーの受信、表示/消去、前後/連続seek後の内容と時刻、停止中・速度変更後の同期。映像成功だけで字幕も成功としない。
- fMP4の通常/字幕付き撮影、解像度・向き・色・映像との時刻、サーバー/写真/両方の各保存結果、操作UIの混入防止。既存TS/VLC経路と比較する。
- fMP4のPiP・音画同期・視聴位置同期、PiP開始待ち/有効中に項目が失敗した場合、画面復帰後の保留復旧、所有元を閉じた後の終了。復帰先の消失/二重再生/古い音声がないこと。
- 同じセッションでfMP4からTS/VLCへ戻れるサーバー契約、Cloudflare Access経由のinit/segment/seek、Range応答。一般的な標準サーバー互換性と、fMP4対応改造サーバーでの成功を分ける。
- 長時間のCPU/GPU/メモリ/発熱/消費電力/画質・フレームレート・ハードウェアデコード。ソース上の既存経路維持を性能実測へ読み替えない。

既存のTS fixtureでのシミュレーターテストは、実際のfMP4/emsg・字幕画像・HEVC撮影フレームやLiveContainerを証明しない。PiP内字幕/実況、L字クロップは今回対象外。実況コメント付き撮影は削除済みのままとする。mainの実機基準版0.26は、新版の実機確認とユーザー了承まで維持する。
